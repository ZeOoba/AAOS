## 2. A2: commit-failure roll-forward (YELLOW, shared-state writer, mandatory REFUTE)

### 2.1 What is wrong today (reproduced from code, `tools/_aaos_common.py:1036-1062`, `tools/lease-task.py:101-160`)
`commit_state_change` stages `<state>.tmp-<pid>`, calls `emit_event` (the commit point), then `os.replace`. If `os.replace` raises after the event is committed, the exception escapes raw; the staged tmp stays; nothing records it. `lease-task` then runs `except BaseException: archive_lock_if_unchanged(...)`, deleting the lock **after `TaskLeased` committed** (§16.1). `complete-task --archive` commits `Completed`, then a second `commit_state_change` for `Archived` (§16.3, §16.15). The `.tmp-<pid>` name is reusable by a later process with the same PID and `OPERATIONS.md` calls such files safe to delete (§16.4).

### 2.2 Items

**A2-a. Durable staged transaction record and `StateCommitError` (core).**
Goal: after the event commits, a failed state apply is detectable, replayable and never silently undone.
Exact changes:
- `tools/_aaos_common.py`: new `class StateCommitError(AaosError)` with `event_id`, `staged_path`, `kind` in {`apply_failed`, `precondition_changed`}. New `staged_dir(project_id, root)` = `projects/<p>/staged/` (new directory; not under `tasks/`, so no `tasks/*.json` glob, no sweep enumeration and no `.tmp-` convention applies, §16.4). Staged file name `sg-<time_ns>-<uuid4hex>.json` (bounded length regardless of task-id length). Content is a wrapper: `{"protocol_version":"1.0","kind":"staged-state","event_id":null|"e-...","state_rel":"tasks/<id>.json","base_sha256":"<hex>|null","precondition":{"lock":{holder,session,acquired,expires}|null},"staged_at":"<iso>","state":{...}}`.
- `commit_state_change` order becomes: (0) **guard:** if `staged/` holds an open record for the same `state_rel`, resolve it first (current state equals the staged state: unlink it as already-applied; otherwise refuse with `StateConflictError` naming the record), so a new transaction never overwrites a pending one; (1) compute `base_sha256` of the current state bytes; read the lock if the transition holds a lease; (2) write the staged file with `atomic_write` (durable before the commit); (3) `emit_event(..., drain=False)` (so no interrupt-prone drain runs inside the window; the drain runs after step (6), best-effort as today); (4) record the returned `event_id` by rewriting the staged file once (atomic_write over its own file; if this fails the event is committed but the wrapper says `event_id: null` — replay then finds the event by the transaction's `refs`+`type`, see test R-9); (5) `apply_staged` (below); (6) on success unlink the staged file as the writer's **own artifact** (A7's `_discard_own_temp` does not exist on `main`; A2 adds a private `_discard_own_staged` that unlinks only a path created in this call, tested to touch nothing else; A7 later folds it into its allowlist); (7) on `EventCommitError` before the commit, unlink the staged file (own artifact) and re-raise unchanged (rollback is legal only here).
- `apply_staged(staged_path, *, budget_s=3.0, clock=time.monotonic, sleep=time.sleep, now=None)`: loop `os.replace(tmp, state)` where the state content is written to a `.tmp-<pid>` sibling only for the instant of the rename (atomic_write semantics; this tmp is never the record of truth). Before **every** attempt, including the first, re-verify: (i) current state bytes hash equals `base_sha256` (or already equals the staged state's hash: then success, idempotent); (ii) if `precondition.lock` is set, the lock file at `lock_path` still equals it field-for-field and is not expired at `now` (ADR-0006 D1: the lock is the authority). Mismatch raises `StateCommitError(kind="precondition_changed")` immediately, no further retries. The retry budget is **elapsed time on the injected clock**, not a count (plan §5). A non-retryable `OSError` (`ENOENT` on the directory, `EACCES` that persists past the budget) raises `apply_failed` when the budget is exhausted.
- On `apply_failed`/`precondition_changed`: best-effort emit `Escalated`, actor `system`, `refs={task, reason:"StateCommitFailed", event:<id>}`, `detail="staged=<basename>"` (≤200 chars by construction: basename is 60 chars). The emission is best-effort: its failure never masks the `StateCommitError`. The escalation is emitted with the new `drain=False` keyword (introduced here in A2-a; A1c-b consumes it) so it spools without a drain.
- CLI callers: **six tools, not four** (`grep commit_state_change(` finds `lease-task:129`, `complete-task:91,141`, `fail-task:122`, `post-handoff:225`, `create-task:154`, `expire-leases:188`; a grep test enumerates them). `create-task` re-run after a failure must not commit a duplicate `TaskCreated` (guard step (0)). `expire-leases` (the scheduled sweep) catches `StateCommitError` **per task**, continues with the remaining tasks, returns non-zero only at the end, and **skips any task with an open staged record** (otherwise every run judges the same unarchived lock again and commits another `LeaseExpired`); its orphan-lock path (`expire-leases.py:155-170`) must not archive a lock that an open `TaskLeased` staged record references. The §6 cutover (supervised pause of `ora-aaos-expire-leases`) is **unconditional** for A2-a. All callers: catch `StateCommitError` **before** the generic handler; print `STATE COMMIT FAILURE: <task> event <id> is committed, state NOT applied; staged <name>; supervised replay required` on stderr and return **exit 5** (the existing durable-commit class; documented in the exit table; decision D5 lets Gabriel pick a new code instead). They must not call `archive_lock_after_commit`, must not call `archive_lock_if_unchanged`, and must not start a second transaction (`complete-task --archive` skips `_archive_task`).
- `lease-task`: the `except BaseException` rollback is narrowed to failures **before** `commit_state_change` returns control after the commit point: it rolls back only for `EventCommitError` and for errors raised before the call. `StateCommitError` passes through with the lock untouched. Because `KeyboardInterrupt`/`SystemExit` can arrive between the commit and the replace, `commit_state_change` converts any `BaseException` raised after the event spool write inside step (3) into `StateCommitError(kind="apply_failed")` with `__cause__` set (a failure of the step-(4) wrapper rewrite is treated the same: step (5) is still attempted, and if it too fails the result is `apply_failed`), then the CLI exits 5 (interrupt becomes a loud failure rather than a lock rollback; `[REFUTE focus]`).

## 3. A1c: inbound validation (YELLOW; split into four PRs)

### 3.1 Design decisions fixed here (each answers a §16 input)
- **Two rule classes.** *Structural* rules (event is an object; schema-valid; `project_id` equals the project whose spool it sits in; timestamp parses; `event_id` present; `detail` ≤ 200) and *advisory* rules (actor unknown to the draining checkout's registry; actor/surface mismatch; a timestamp beyond the skew window, `TimestampFuture`). **Advisory rules never reject, in shadow or hard mode** (§16.6, §16.7: Code's own actors are free text and tests use `a`, `h`; the registry is per checkout, so a newer worktree's actor would be rejected after commit by an older draining checkout). Only structural failures can ever reach hard mode, and only after AMD-0004b. **To resolve in AMD-0004b:** AMD-0003 C justifies routing denials under actor `system` because "AMD-0004 would quarantine" an unregistered holder; under advisory-only actors that rationale no longer holds, so AMD-0004b should correct that sentence. Plan §15's "registry **or** `system`" actor rule is likewise superseded (D3).
- **Emit-time behaviour with an unreadable registry (§16.6): proceed.** `emit_event` never gains a new failure mode on the commit path. It logs a one-line WARNING and spools. (Option B in D3 is the stricter alternative.)
- **Tags live in a first-seen ledger, not in the event** (§16.12). The NDJSON content is unchanged. Ledger: `projects/<p>/events/inbound-ledger.ndjson`, appended only by the drain-lock holder, keyed on `(file_key, sha256(content))` where `file_key` is the file name truncated to 64 characters plus `-` plus the first 16 hex of the name's sha256 (names are at most 255 characters on NTFS), one line per first sight: `{"seen":"<iso>","file":"<file_key>","sha256":"...","event_id":"...","mode":"shadow","would_reject":[...],"advisory":[...]}`. Never deleted; durable; written with the pre-replace hash guard (A1b) so it inherits the drain's stale-base protection.
- **Escalation is aggregated, after the lock release, from fixed fields only** (plan §4): one `Escalated(reason="InboundInvalid")`, actor `system`, `detail="count=N"` (N is the number of **first-seen** would-reject entries in this drain, so re-draining does not repeat it; each ledger line carries `escalated: bool`, set after the escalation commits, and a later drain escalates any line still `false`, so a crash or failed emit between the ledger append and the `Escalated` event loses nothing), no filenames, no free text from the event.
- **Skew window (§16.14, M22):** structural check on the parsed timestamp before `read_events` sorts. Recommended semantics (decision D4): an event is *out-of-window* (advisory) if its timestamp is more than `SKEW` (5 min, the ratified default) **after** its first-seen time in the ledger; past timestamps are never out-of-window (late arrival is tolerated and counted as `late_by_s` in the ledger). An out-of-window event is **flagged and sorted by its first-seen time instead of its stamped time**, never dropped. Annotation is returned by a new `read_events_annotated(project_id, root=)` that yields `(event, flags)` pairs; `read_events` keeps its signature and return type so no existing consumer changes. **§16.14 is therefore only half answered: `fail-task`'s DoubleFailure scan and `project-notion` still order by stamped time until they are moved to the annotated view. OPEN (part of D4): move those two consumers in A1c-b, or defer to B1/B4.**
